## Исправления Oscilloscope GUI - BMI30.200.py

### 🐛 Баг: "Осциллограмма показывает только 1 семпл вместо 912"

#### Проблема
При запуске потока с профилем 1 или 2, осциллограф в GUI отображал только 1 семпл вместо ожидаемых 912 семплов, хотя в статусе показывалось "BUF 912".

#### Корневая причина
Была проблема с синхронизацией между Python переменной `self.view_len` (желаемая длина вывода) и значением Qt слайдера `slider_len.value()` (текущее значение в GUI):

1. При получении первого буфера данных код выполнял:
   ```python
   self.view_len = 912  # сразу устанавливается в Python
   self.slider_len.setValue(912)  # отправляется команда GUI
   ```

2. На первый же вызов отрисовки:
   ```python
   vlen = max(1, min(int(self.slider_len.value()), self.base_buf_len))
   # slider_len.value() еще не обновилось = 0 (асинхронно!)
   # Итог: vlen = max(1, min(0, 912)) = 1  ❌
   ```

#### ✅ Решение
Использовать `self.view_len` как основной источник истины вместо `slider_len.value()`:

**Было:**
```python
vlen = max(1, min(int(self.slider_len.value()), self.base_buf_len))
```

**Стало:**
```python
# Используем self.view_len как основной источник истины
vlen = max(1, min(self.view_len, self.base_buf_len))
```

Почему это работает:
- `self.view_len` обновляется синхронно в Python коде
- `slider_len.value()` зависит от обработки событий в Qt (асинхронно)
- Когда пользователь двигает слайдер, `_on_slider_len()` синхронизирует `self.view_len` с новым значением

### Изменения в коде

#### 1. Строка ~490: Fix основной отрисовки
```python
# Используем self.view_len как основной источник истины (более надежно чем slider_len.value())
vlen = max(1, min(self.view_len, self.base_buf_len))
```

#### 2. Строка ~333: Сброс слайдера при остановке
```python
self.slider_len.setValue(0)  # <-- ВАЖНО: сброс значения слайдера
```
