# ИСПРАВЛЕНИЕ: "1 семпл вместо 912" на осциллограмме

## Проблема
При запуске потока данных осциллограф показывал только 1 семпл вместо 912, хотя статус показывал "BUF 912".

## Корневая причина
Баг был вызван синхронизацией между `self.view_len` (переменная, которая хранит желаемую длину отображения) и `slider_len.value()` (значение слайдера в GUI):

1. При инициализации буфера (получение первых данных):
   - `self.view_len = 912` (устанавливается в переменную)
   - `slider_len.setValue(912)` (отправляется команда GUI)
   - Но GUI может не обновить `slider_len.value()` сразу (асинхронно)

2. На первом же вызове отрисовки:
   - Старый код: `vlen = max(1, min(int(slider_len.value()), 912))`
   - `slider_len.value()` возвращает 0 (еще не обновилось)
   - Результат: `vlen = max(1, min(0, 912)) = 1` ← БАГИ

## Решение
Использовать `self.view_len` как основной источник истины вместо `slider_len.value()`:

**БЫЛО:**
```python
vlen = max(1, min(int(self.slider_len.value()), self.base_buf_len))
```

**СТАЛО:**
```python
# Используем self.view_len как основной источник истины
vlen = max(1, min(self.view_len, self.base_buf_len))
```

Это надежнее потому что:
- `self.view_len` сразу обновляется в коде Python
- `slider_len.value()` зависит от обработки событий GUI (асинхронно)
- Мы все равно синхронизируем слайдер с `self.view_len` когда пользователь его двигает через `_on_slider_len()`

## Дополнительные исправления
1. При остановке потока - явно сбросить значение слайдера:
   ```python
   self.slider_len.setValue(0)  # <- ВАЖНО: сброс значения слайдера
   ```
   Это предотвращает "залипание" старого значения при переключении профилей.

## Файлы изменены
- `host/BMI30.200.py`:

  - Строка 333: явный сброс `slider_len.setValue(0)` при закрытии потока

## Тестирование
- Профиль 1 (200 Hz): должен показывать 912 семплов
- Профиль 2 (300 Hz): должен показывать 912 семплов
- Переключение профилей: плавное, без потери синхронизации
