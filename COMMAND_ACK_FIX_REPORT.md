# Исправление потери управления устройством после USB-восстановления

## ✅ Выполненные изменения

### Проблема
После зависания USB и восстановления связи (watchdog stage 2-3) хост теряет управление устройством:
- Переключение режимов не работает (профиль 3 показывает 200 семплов вместо 600)
- Команды отправляются, но не выполняются на устройстве
- Хост-код считает их успешными и попадает в несогласованное состояние

**Корневая причина**: Отправка команд без проверки подтверждения (ACK) от устройства.

### Решение

#### 1️⃣ Добавлена проверка ACK в USBStream (`host/usb_vendor/usb_stream.py`)

Новый метод `send_cmd_and_wait_ack()`:
```python
def send_cmd_and_wait_ack(self, cmd, payload: bytes, ack_timeout_ms=500):
    """Отправить команду и ждать ACK (0x80) от устройства перед возвратом."""
```

**Функциональность**:
- ✓ Отправляет команду на EP_OUT
- ✓ Синхронно читает ответ с EP_IN с таймаутом
- ✓ Проверяет получение ACK (0x80 = RSP_ACK)
- ✓ Возвращает True/False

#### 2️⃣ Обновлены критические команды в BMI30.200.py

Все команды управления режимами теперь требуют ACK перед обновлением состояния:

| Место | Команды | Статус |
|-------|---------|--------|
| Watchdog-восстановление | SET_PROFILE, SET_FRAME_SAMPLES, Частота | ✅ Обновлено |
| Режим LATEST | SET_WINDOWS, SET_STREAM_MODE=0, SET_ASYNC=1 | ✅ Обновлено |
| Режим LOSSLESS_ROI | SET_WINDOWS, SET_STREAM_MODE=1, SET_ASYNC=0 | ✅ Обновлено |
| Режим AVG_ROI (основной) | SET_WINDOWS, SET_STREAM_MODE=2, SET_ASYNC=0 | ✅ Обновлено |
| Обновление avg_n во время работы | SET_STREAM_MODE=2 + avg_n | ✅ Обновлено |
| Инициализация (initseq) | SET_WINDOWS, SET_STREAM_MODE, SET_PROFILE | ✅ Обновлено |
| Восстановление параметров | SET_STREAM_MODE (avg_n) | ✅ Обновлено |
| Изменение avg_n (меню) | SET_STREAM_MODE (avg_n) | ✅ Обновлено |

#### 3️⃣ Логика обработки ошибок

```python
if hasattr(self.stream, 'send_cmd_and_wait_ack'):
    cmd_ok = self.stream.send_cmd_and_wait_ack(CMD_..., payload, ack_timeout_ms=500)
else:
    self.stream.send_cmd(CMD_...)  # Fallback
    cmd_ok = True

if not cmd_ok:
    print("[CONTEXT] CMD ACK not received")
    return  # Abort if critical
```

**Стратегия**:
- ✓ При неудаче - НЕ обновляется локальное состояние
- ✓ Функция возвращает управление для повтора
- ✓ Graceful degradation (работает с старыми версиями без ACK)

## 🔄 Обратная совместимость

Код полностью обратно совместим:
- Если метод `send_cmd_and_wait_ack()` недоступен → использует fallback `send_cmd()`
- Старые версии USBStream продолжат работать без ACK-проверки
- Новые версии получают полную ACK-верификацию

## 📝 Ожидаемое поведение

### До фиксации (BUG):
```
1. USB-зависание
2. Watchdog отправляет SET_PROFILE(3)
3. Команда может не выполниться на устройстве
4. Хост думает что режим 3 активен
5. ➡️ Конфликт состояния - режим 3 не работает!
```

### После фиксации (FIXED):
```
1. USB-зависание
2. Watchdog отправляет SET_PROFILE(3) с ACK-проверкой
3. Если ACK не получен → логирует "[WATCHDOG] SET_PROFILE ACK not received"
4. Не обновляет локальное состояние
5. ➡️ Хост и устройство остаются синхронизированными
```
