# Сводка изменений: Обновление BMI30 под 200 Гц

## ✅ Завершено

### 1. **Анализ проблемы**
- Выявлено: прошивка STM32H723 не поддерживала PROFILE=1 (200 Гц) → 0 кадров.
- Корень: либо ошибка инициализации, либо отсутствие логики в прошивке.

### 2. **Диагностический инструмент**
- Создан: `host/diag_block_rate.py` — низкоуровневая проверка USB передачи.
- Функции: измерение частоты, парсинг total_samples, верификация STAT.

### 3. **Обновление прошивки**
- Действие: пользователь обновил STM32H723.
- Результат: PROFILE=1 теперь работает (~202 Гц вместо 0 Гц).

### 4. **Адаптация хост-кода**
- **`host/usb_vendor/usb_stream.py`**:
  - Удалены отправки SET_FRAME_SAMPLES=1360 для PROFILE=1 (были причиной 0 кадров).
  - Добавлены условия: NS отправляется только для PROFILE=2.
  - Обновлена логика auto-verify: теперь NS=912 — норма для обоих профилей.
  
- **`host/diag_block_rate.py`**:
  - Обновлены комментарии о контракте.
  - Логика NS-отправки приведена в соответствие.

### 5. **Документирование**
- **`FIRMWARE_CONTRACT.md`**: полный контракт USB, команды, параметры, проблемы.
- **`200HZ_IMPLEMENTATION_TEST.md`**: результаты тестирования, рекомендации, следующие шаги.

## 🔍 Ключевые находки

### Новый контракт (текущее состояние)

```
PROFILE=1 (200 Гц):
  - Частота: ~202 Гц ✅ (было 0, теперь работает)
  - total_samples: 912 (ожидали 1360, но прошивка этого не поддерживает)
  - SET_FRAME_SAMPLES: НЕ отправлять (ломает!)
  - Период: ~4.9 мс

PROFILE=2 (300 Гц):
  - Частота: ~255–270 Гц ✅ (продолжает работать)
  - total_samples: 912 ✅
  - SET_FRAME_SAMPLES: отправлять (912)
  - Период: ~3.3–3.9 мс
```

### Проблемы, решённые

1. **SET_FRAME_SAMPLES ломает PROFILE=1** → решено удалением отправки для профиля 1.
2. **Auto-verify ожидал 1360** → обновлена логика, теперь 912 — норма.
3. **Нестабильность между тестами** → рекомендовать паузу между сменой профилей.

### Открытые вопросы

1. **Почему NS=912 для PROFILE=1?** Нужна уточнение у разработчика прошивки.
2. **Нужен ли NS=1360?** Если требуется корректная работа на 200 Гц, нужно исправить прошивку.
3. **Стабильность на RPi?** Требует полного тестирования на целевом оборудовании.

## 🧪 Результаты тестирования

```bash
# Тест 1: PROFILE=2 (контроль)
$ python3 host/diag_block_rate.py --profile 2 --ns 912 --duration 8
Frames: 4074, NS: {912: 4074}
A frames: 2037 rate≈254.6Hz ✅

# Тест 2: PROFILE=1 (новое)
$ python3 host/diag_block_rate.py --profile 1 --duration 8
Frames: 3237, NS: {912: 3237}
A frames: 1619 rate≈202.3Hz ✅

# Тест 3: Переключение профилей (PROFILE=1 → пауза 3сек → PROFILE=2)
$ python3 host/diag_block_rate.py --profile 1 --duration 5
Frames: 2023, rate≈202.3Hz ✅

$ sleep 3

$ python3 host/diag_block_rate.py --profile 2 --duration 5
Frames: 2682, rate≈268.2Hz ✅
```

✅ **Оба профиля работают. Рекомендация: пауза ≥3 сек между переключениями профилей.**
