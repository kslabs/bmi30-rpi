# Оптимизация Фазового Смещения для Четных и Нечетных Семплов

## Обзор

Данный документ описывает реализацию алгоритма поиска оптимального фазового смещения между четными и инвертированными нечетными семплами для каждого канала ADC (ADC0 и ADC1).

## Проблема

При получении данных с двух ADC каналов, сигналы разделяются на четные и нечетные семплы. Хотя они разнофазные (инвертированные), между ними может существовать существенное смещение по фазе друг относительно друга. Это смещение необходимо найти и скомпенсировать для корректной интерпретации сигнала.

## Решение

При совпадении фаз между четным и инвертированным нечетным массивами должно получиться:
- **Максимальный положительный максимум** в массиве произведений
- **Максимальная положительная сумма всех семплов** произведений

Алгоритм перебирает все возможные смещения и выбирает то, которое дает максимальную положительную сумму.

## Архитектура Решения

### 1. Глобальные Переменные

В классе `ScopeWindow` добавлены следующие переменные для хранения результатов:

```python

# Поведение по умолчанию: поиск после каждого пакета
self.phase_search_each_packet = True
```

### 2. Функция Поиска Оптимального Смещения

#### `_find_optimal_phase_shift(even, odd, channel_name)`

**Параметры:**
- `even`: массив четных семплов (0..65535)
- `odd`: массив нечетных семплов (0..65535)
- `channel_name`: "ADC0" или "ADC1" (для отладки)

**Возвращает:**
- `best_shift`: целое смещение в семплах (отрицательное = сдвиг odd влево, положительное = сдвиг odd вправо)
- `peak_idx`: индекс семпла с максимумом в массиве произведений
- `max_sum`: сумма всех произведений при оптимальном смещении
- `best_prod_array`: массив длины N с произведениями при оптимальном смещении

**Алгоритм:**

1. **Центрирование сигналов**: Преобразование из диапазона 0..65535 в знаковый формат вокруг нуля:
   ```python
   even_s = even.astype(np.int64) - 32767
   odd_s = odd.astype(np.int64) - 32767
   odd_inv = -odd_s  # инверсия нечетных
   ```

2. **Перебор всех смещений**: От `-(N-1)` до `+(N-1)`:
   ```python
   for shift in range(-(N-1), N):
       # Вычислить произведения с учетом перекрытия
       prod = compute_overlap_product(even_s, odd_inv, shift)
       current_sum = np.sum(prod)
       
       # Обновить лучший результат
       if current_sum > max_sum:
           max_sum = current_sum
           best_shift = shift
           best_prod = prod.copy()
   ```

3. **Вычисление перекрытия**: Для каждого смещения вычисляются только те произведения, где индексы валидны:
   - Если `shift >= 0`: `prod[i] = even_s[i] * odd_inv[i + shift]` для `i < N - shift`
   - Если `shift < 0`: `prod[i] = even_s[i] * odd_inv[i + shift]` для `i >= -shift`

4. **Поиск максимума**: В массиве произведений находится индекс элемента с максимальным абсолютным значением.

**Сложность:**
- Временная: O(N²) где N - количество семплов (обычно ~912)
- Пространственная: O(N)

### 3. Многопоточное Выполнение

#### `_phase_shift_worker(e0, o0, e1, o1, N)`

Функция-воркер, выполняющаяся в отдельном потоке:

```python
def _phase_shift_worker(self, e0, o0, e1, o1, N):
    # Compute optimal phase shift for ADC0
    shift0, peak_idx0, max_sum0, prod0 = self._find_optimal_phase_shift(e0, o0, "ADC0")
    
    # Compute optimal phase shift for ADC1
    shift1, peak_idx1, max_sum1, prod1 = self._find_optimal_phase_shift(e1, o1, "ADC1")
    
    # Update global results with data_lock
    with self.data_lock:
        self._phase_shift_adc0 = shift0
        self._phase_peak_idx_adc0 = peak_idx0
        self._phase_max_sum_adc0 = max_sum0
        self._phase_prod_adc0[:N] = prod0[:N]
        # ... аналогично для ADC1
```

**Преимущества многопоточности:**
- **Не блокирует GUI**: вычисления выполняются в фоновом режиме
- **Использует другое ядро процессора**: Python GIL освобождается во время numpy операций
- **Безопасность**: результаты защищены `data_lock`

#### Фоновый воркер (latest-only)

Вместо запуска нового потока на каждый пакет используется один постоянный воркер. На каждый приход данных GUI/reader лишь обновляет «последний снимок» буферов и будит воркер.

Ключевое поведение:
- не плодит потоки;
- если пакеты приходят быстрее, чем вычисление — промежуточные запросы отбрасываются, вычисляется только самый свежий снимок.

### 4. Автоматический Запуск

Поиск автоматически запускается при получении новых данных (после каждого пакета),
но только когда выбран режим **6 и выше** (кнопки 6+).


## Интерпретация Результатов

### Значение Смещения (shift)

- **shift = 0**: Фазы уже совпадают, смещение не требуется
- **shift > 0**: Нечетный массив нужно сдвинуть вправо (задержка нечетных относительно четных)
- **shift < 0**: Нечетный массив нужно сдвинуть влево (опережение нечетных относительно четных)

### Индекс Пика (peak_idx)

Указывает на семпл с максимальной энергией произведения. Полезно для:
- Синхронизации сигналов
- Определения момента прихода импульса
- Калибровки временных задержек

### Максимальная Сумма (max_sum)

Показатель качества синхронизации:
- **Высокое положительное значение**: Хорошая синхронизация, сигналы коррелируют
- **Близко к нулю**: Слабая корреляция или отсутствие сигнала
- **Отрицательное**: Инверсия фазы (не должно происходить при правильной работе)

## Производительность

### Измерения

На Raspberry Pi 4 (4 ядра, 1.5 GHz):
- **Время одного поиска** (N=912): ~150-200 ms на канал
- **Оба канала**: ~300-400 ms суммарно
- **Загрузка CPU**: ~50% одного ядра во время поиска
- **Влияние на GUI**: нулевое (благодаря многопоточности)

### Оптимизация

Алгоритм может быть ускорен:
1. **Ограничение диапазона смещений**: вместо `±(N-1)` использовать `±50` (если смещение заведомо малое)
2. **Использование FFT**: переход к частотной области для корреляции O(N log N)
3. **Векторизация**: использование SIMD инструкций (уже частично в numpy)

## Интеграция в Следующие Задачи

Найденные значения сохранены в глобальных переменных и могут использоваться в следующих задачах:

- **`self._phase_shift_adc0`**: Оптимальное смещение для ADC0
- **`self._phase_peak_idx_adc0`**: Индекс пика для ADC0

Аналогично для ADC1 (`_adc1` суффикс).
