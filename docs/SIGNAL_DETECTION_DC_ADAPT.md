# Детекция сигнала + управление DC-adapt (host)

## Идея

- Для каждого канала (ADC0/ADC1) берём **максимальный уровень** корреляционного массива.
- В хост-коде он считается как максимум по **нормализованному per-sample product** (примерно $[-1..1]$), далее переводится в устойчивый диапазон **0..65535**.
- Порог **адаптируется**: если максимум больше порога → `+2`, если меньше → `-1`.
- Если максимум **больше чем в 2 раза** превышает порог **второй раз подряд**, считаем что **сигнал пойман**.

## Управление адаптацией DC на устройстве

Используется команда `CMD_SET_DC_ADAPT` (firmware-dependent).

```python
from usb_vendor.usb_stream import USBStream, CMD_SET_DC_ADAPT

stream = USBStream()

# При детекции сигнала — заморозить адаптацию на устройстве
stream.send_cmd(CMD_SET_DC_ADAPT, b'\x00')

# Сигнал пропал — возобновить адаптацию на устройстве
stream.send_cmd(CMD_SET_DC_ADAPT, b'\x01')
```

Примечание: если в прошивке/хосте код команды отличается, можно переопределить через переменную окружения:

- `BMI30_CMD_SET_DC_ADAPT=0x1B`

## PWM индикация (Raspberry Pi)

- Выход: **PWM0 на GPIO12** (BCM 12).
- При подтверждении детекции запускается один независимый цикл аппаратного PWM:
  базовый тон 150 мс, затем phase-зависимый тон 150 мс, после чего эта пара
  повторяется без паузы до окончания `HOLD`. Промежуточные обновления
  детектора не перезапускают и не пересоздают этот цикл.
- `Minimum tone cycles` задаёт число последовательных циклов расчёта
  detector/phase до запуска звука. Детекция, закончившаяся раньше, не включает
  аппаратный таймер.
- `Minimum sound, ms` удерживает уже запущенный тон не короче заданного
  времени, даже если `HOLD` завершился раньше.
- Звук и LED являются двумя независимыми выходами детектора: каждый имеет
  собственный переключатель `Enabled`. Фильтр запуска и минимальная
  длительность относятся только к звуку и не меняют длительность LED.
- Частота выбирается в момент срабатывания по каналу и найденному phase shift:
  - ADC0 (Upper): 1000..3000 Гц
  - ADC1 (Lower): 2000..4000 Гц
  в зависимости от найденного phase shift между even/odd.

Хост использует только аппаратный `PWM0_CHAN0` через Linux PWM subsystem
(`/sys/class/pwm/pwmchip0/pwm0`). Программные `lgpio`, `pigpio` и
`RPi.GPIO` fallback для звука запрещены: при недоступном аппаратном PWM
звуковой выход остаётся выключенным и сообщает об ошибке.

Тестовые `Upper`/`Lower` взаимоисключающие и повторяют соответствующую
двухтоновую пару 150+150 мс до снятия галочки.

Отключить звук можно так:
- `BMI30_BEEP_ENABLE=0`
