# Контракт хоста и прошивки (STM32H723, IF#2, Bulk EP)

## Статус после обновления

✅ **Профиль 1 (200 Гц)**: Работает стабильно
- PROFILE=1 → задаём 200 Гц (реально получаем ≈176 Гц)
- total_samples=912 на каждый кадр (A и B)

✅ **Профиль 2 (300 Гц)**: Работает стабильно
- PROFILE=2 → задаём 300 Гц (реально получаем ≈280 Гц)
- total_samples=912 на каждый кадр (A и B)

## Контракт (текущее состояние)

### Основные команды (Bulk OUT 0x03)

| Команда | Код | Payload | Эффект |
|---------|-----|---------|--------|
| SET_PROFILE | 0x14 | u8: 1 или 2 | Переключить на 200 Гц (p=1) или 300 Гц (p=2) |
| SET_FULL_MODE | 0x13 | u8: 1 или 0 | Полный режим (всегда 1 для хоста) |
| SET_FRAME_SAMPLES | 0x17 | u16 LE | ⚠️ Работает только для p=2; для p=1 игнорировать |
| START_STREAM | 0x20 | — | Начать передачу |
| STOP_STREAM | 0x21 | — | Остановить передачу |
| SET_BLOCK_RATE | 0x11 | u16 LE | (опционально) Подсказка частоты; прошивка может игнорировать |

### Формат кадра (Bulk IN 0x83)

**Заголовок (32 байта):**
```
Offset  | Size | Поле
--------|------|--------
0-1     | u16  | MAGIC = 0xA55A (LE)
2       | u8   | version
3       | u8   | flags (VF_ADC0=0x01, VF_ADC1=0x02)
4-7     | u32  | seq (монотонный счётчик)
8-11    | u32  | timestamp (мкс)
12-13   | u16  | total_samples (длина payload/2)
14-15   | u16  | zone_count
16-19   | u32  | zone1_offset
20-23   | u32  | zone1_length
24-31   | u64  | reserved/crc (опционально)
```

**Payload:** `total_samples * 2` байт (16-bit int16 слова)

**Флаги:**
- VF_ADC0 (0x01): Кадр канала 0 (A)
- VF_ADC1 (0x02): Кадр канала 1 (B)
- Чередование: A, B, A, B, ...

### Параметры по профилю

| Параметр | PROFILE=1 (200 Гц) | PROFILE=2 (300 Гц) |
|----------|-------------|-------------|
| Частота блока (задаём) | 200 Гц | 300 Гц |
| Частота (реально) | ≈176 Гц | ≈280 Гц |
| total_samples | 912 | 912 |
| Период блока | ≈5.7 мс | ≈3.6 мс |

## Проблемы и рекомендации

### 1. total_samples для профиля 1

**Текущее:** PROFILE=1 → total_samples=912
**Ожидаемое:** PROFILE=1 → total_samples=1360

**Причина:** Неясна (возможно, ограничение ДМА или конфигурации ADC в прошивке).

**Решение:**
- Опция A: Обновить прошивку, чтобы PROFILE=1 действительно генерировал 1360 сэмплов.
- Опция B: Обновить хост использовать 912 для обоих профилей (текущее решение).

**Рекомендация:** Опция A лучше, так как позволит маштабировать дополнительные профили. Для срочного решения используйте Опцию B.

### 2. SET_FRAME_SAMPLES ломает PROFILE=1

**Наблюдение:** Если послать SET_FRAME_SAMPLES при активном или предыдущем PROFILE=1, передача прекращается.

**Рекомендация:** 
- На хосте: **Не посылать SET_FRAME_SAMPLES для PROFILE=1** (только для PROFILE=2).
- В прошивке: Валидировать NS перед применением; если NS несовместим с текущим профилем, игнорировать или вернуть ошибку вместо молчаливого разрыва.

### 3. Частота ≈202 Гц вместо ровно 200 Гц

**Причина:** USB-тайминги, погрешность источника тактирования.

**Действие:** Нормально; хост допускает ±5% вариацию.

### 4. Проверка готовности (EP0 GET_STATUS)

**Текущее:** STAT возвращается после START, alt1 = 1, out_armed = 1.

**Хорошо:** Готовность сигнализируется корректно.

## Процедура проверки

### На хосте (скрипт `host/diag_block_rate.py`)

```bash
# Тест 300 Гц (должно быть ~3000+ кадров за 6 сек, NS=912)
python3 host/diag_block_rate.py --profile 2 --ns 912 --duration 6

# Тест 200 Гц (должно быть ~1200+ кадров за 6 сек, NS=912 текущий)
python3 host/diag_block_rate.py --profile 1 --duration 6
```

**Ожидаемый результат:**
- Оба профиля выдают кадры.
- total_samples=912 для обоих.
- Частота: ~270 Гц для профиля 2, ~200 Гц для профиля 1.

## Обновление хост-кода

**Текущее поведение хоста (`host/usb_vendor/usb_stream.py`):**
- При PROFILE=1: отправляет FRAME_SAMPLES=1360, получает молчание.
- При PROFILE=2: отправляет FRAME_SAMPLES=912, получает кадры 912.

**Требуемое изменение:**
- Для PROFILE=1: **не отправлять SET_FRAME_SAMPLES**, использовать прошивкой-выбранный NS (912).
- Или: дождитесь исправления прошивки под PROFILE=1 → NS=1360.
