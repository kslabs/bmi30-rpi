# Автосохранение осциллограмм при детекции сигнала

## Обзор

Система автоматически сохраняет осциллограммы при срабатывании детектора сигнала, включая кадры **ДО**, **ВО ВРЕМЯ** и **ПОСЛЕ** события. Это позволяет анализировать шумы и условия, приводящие к ложным срабатываниям.

## Активация

```bash
# Включить автосохранение
export BMI30_AUTO_CAPTURE=1

# Настройка параметров
export BMI30_CAPTURE_PRE=30    # Кадров ДО срабатывания (по умолчанию 30)
export BMI30_CAPTURE_POST=10   # Кадров ПОСЛЕ потери сигнала (по умолчанию 10)
export BMI30_CAPTURE_DIR=./captures  # Папка для сохранения (по умолчанию ./captures)

# Запуск GUI
python host/BMI30.200.py
```

## Принцип работы

### 1. Кольцевой буфер
- Постоянно хранит последние N кадров (по умолчанию 50)
- Обновляется каждый кадр независимо от детекции
- Не влияет на производительность GUI

### 2. Фазы захвата

**IDLE** → **TRIGGERED** → **RECORDING** → **FINALIZING** → **IDLE**

#### Фаза TRIGGERED (момент срабатывания)
- Срабатывает при первом fire детектора (🔊)
- Копирует последние PRE кадров из кольцевого буфера
- Переходит в фазу RECORDING

#### Фаза RECORDING (удержание сигнала)
- Записывает каждый кадр пока детектор в состоянии HOLD (❄️)
- Продолжается до потери сигнала

#### Фаза FINALIZING (после потери)
- Начинается когда сигнал потерян (DC адаптация возобновлена)
- Записывает ещё POST кадров
- Сохраняет все данные в NPZ файл
- Возвращается в IDLE

### 3. Структура сохраненных данных (NPZ формат)

**Файл:** `captures/capture_YYYYMMDD_HHMMSS.npz`

**Массивы данных (shape: [n_frames, buf_len]):**
- `data0_even` - ADC0 чётные пакеты (uint16)
- `data0_odd` - ADC0 нечётные пакеты (uint16)
- `data1_even` - ADC1 чётные пакеты (uint16)
- `data1_odd` - ADC1 нечётные пакеты (uint16)

**Временные метки:**
- `timestamps` - абсолютное время каждого кадра (float64)
- `trigger_time` - время срабатывания детектора

**Последовательности:**
- `seq0_even`, `seq0_odd` - sequence numbers ADC0
- `seq1_even`, `seq1_odd` - sequence numbers ADC1

**Состояние детектора для каждого кадра:**
- `det_thr0`, `det_thr1` - пороговые уровни
- `det_lvl0`, `det_lvl1` - измеренные уровни (product max)
- `det_shift0`, `det_shift1` - phase shifts
- `det_amp0`, `det_amp1` - амплитуды сигнала (abs(u16-32768))
- `det_hold0`, `det_hold1` - флаги удержания
- `det_frozen` - флаг заморозки DC адаптации

**Метаданные сессии:**
- `profile` - профиль частоты (1=200Hz, 2=300Hz)
- `freq_hz` - частота дискретизации
- `avg_n` - количество усредняемых буферов
- `stream_mode` - режим потока
- `det_source` - источник детектора ('norm' или 'prod')
- `det_ratio` - пороговый коэффициент
- `reason` - причина срабатывания (строка)
- `n_frames` - количество кадров
- `buf_len` - длина буфера

## Просмотр сохранённых данных

### Viewer GUI

```bash
# Просмотр capture файла
python host/view_capture.py captures/capture_20260115_143052.npz
```

**Управление:**
- `← →` или `A D` - предыдущий/следующий кадр
- `Space` - пауза/воспроизведение
- `Home` / `End` - первый/последний кадр
- `1-5` - скорость воспроизведения (1x, 2x, 5x, 10x, 20x)

**Отображение:**
- Две осциллограммы (ADC0/ADC1)
- Чётные/нечётные пакеты разными цветами
- Информация о кадре и состоянии детектора
- Относительное время от момента срабатывания

### Программный анализ

```python
import numpy as np

# Загрузка данных
data = np.load('captures/capture_20260115_143052.npz')

# Метаданные
n_frames = int(data['n_frames'][0])
trigger_time = float(data['trigger_time'][0])
reason = str(data['reason'][0])

print(f"Frames: {n_frames}")
print(f"Trigger: {reason}")

# Анализ кадра
frame_idx = 20  # Например, 20-й кадр
timestamp = float(data['timestamps'][frame_idx])
rel_time = timestamp - trigger_time  # Время относительно срабатывания

# Данные осциллограмм
adc0_even = data['data0_even'][frame_idx]
adc0_odd = data['data0_odd'][frame_idx]

# Состояние детектора
thr0 = int(data['det_thr0'][frame_idx])
lvl0 = int(data['det_lvl0'][frame_idx])
frozen = bool(data['det_frozen'][frame_idx])

print(f"Frame {frame_idx}: t={rel_time:+.3f}s thr={thr0} lvl={lvl0} frozen={frozen}")
```

## Примеры использования

### 1. Анализ ложных срабатываний

Когда детектор часто срабатывает на шум:
1. Включить `BMI30_AUTO_CAPTURE=1`
2. Дождаться срабатывания
3. Проверить сохранённые captures
4. Просмотреть кадры **ДО** срабатывания
5. Найти характерные шумовые паттерны

### 2. Настройка порогов

Для подбора оптимальных порогов детектора:
1. Собрать несколько captures с разными сигналами
2. Проанализировать распределение `det_lvl0/det_lvl1`
3. Сравнить с `det_thr0/det_thr1`
4. Скорректировать `BMI30_DETECT_RATIO`

### 3. Отладка phase shifts

При нестабильных phase shifts:
1. Просмотреть `det_shift0/det_shift1` по всем кадрам
2. Проверить корреляцию с амплитудами
3. Найти момент когда shift меняется

## Производительность

**Влияние на систему:**
- Кольцевой буфер: ~2-5 МБ RAM (50 кадров × 4 канала × 2048 samples)
- Push frame: ~0.1 мс (копирование данных)
- Сохранение NPZ: ~10-50 мс (выполняется в конце сессии, не блокирует GUI)

**Рекомендации:**
- Для длительной работы установить `BMI30_CAPTURE_PRE=20` (меньше RAM)
- Периодически очищать папку captures
- NPZ файлы сжаты (compression), типичный размер 500 КБ - 2 МБ

## Устранение проблем

**Проблема:** Файлы не сохраняются
- Проверить что `BMI30_AUTO_CAPTURE=1`
- Убедиться что папка captures создана и доступна для записи
- Проверить консоль на ошибки создания директории

**Проблема:** Слишком много файлов
- Увеличить `BMI30_DETECT_RATIO` (меньше срабатываний)
- Увеличить `BMI30_DETECT_COOLDOWN` (больше пауза между срабатываниями)

**Проблема:** Не хватает PRE кадров
- Увеличить `BMI30_CAPTURE_PRE=50`
- Проверить что детектор не срабатывает сразу после старта (warmup период)
