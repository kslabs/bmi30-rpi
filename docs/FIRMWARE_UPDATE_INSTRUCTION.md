## ⚠️ Известные проблемы и ограничения

### Проблема 1: total_samples = 912 для обоих профилей
**Статус:** ⚠️ ТРЕБУЕТ УТОЧНЕНИЯ

**Описание:**
- Ожидалось: PROFILE=1 → 1360 сэмплов, PROFILE=2 → 912 сэмплов
- Текущее: PROFILE=1 → 912 сэмплов, PROFILE=2 → 912 сэмплов

**Что это значит:**
- Период кадра PROFILE=1: 912/200 = 4.56 мс (ожидалось 6.8 мс)
- Может быть недостаточной точностью для некоторых приложений

**Что нужно в прошивке:**
- Проверить: является ли 912 техническим ограничением или ошибкой?
- Если ограничение: обновить документацию
- Если ошибка: добавить поддержку NS=1360 для PROFILE=1

### Проблема 2: SET_FRAME_SAMPLES ломает PROFILE=1
**Статус:** ✅ ИСПРАВЛЕНО НА ХОСТЕ

**Что произошло:**
- Команда 0x17 (SET_FRAME_SAMPLES) при PROFILE=1 приводила к 0 кадров
- Хост-код теперь НЕ отправляет эту команду для PROFILE=1

**Что нужно в прошивке:**
- Добавить валидацию SET_FRAME_SAMPLES
- Если NS несовместим с PROFILE, вернуть ошибку вместо молчания
- Или гарантировать, что SET_FRAME_SAMPLES только для конкретного профиля

### Проблема 3: Требуется пауза между переключениями
**Статус:** 🟡 ДОКУМЕНТИРОВАНО, НО ТРЕБУЕТ ОПТИМИЗАЦИИ

**Текущее:**
- После смены PROFILE требуется ≥3 сек перед START
- Иначе первый тест может вернуть 0 кадров

**Что нужно в прошивке:**
- Сделать рестарт профилей более чистым
- Или гарантировать атомарность PROFILE/NS/START последовательности

### Шаг 2: Исправить SET_FRAME_SAMPLES
**Действие:** В прошивке добавить валидацию NS
```c
// firmware/usb_handler.c (pseudocode)
case CMD_SET_FRAME_SAMPLES:
    ns = *(uint16_t*)payload;
    if (current_profile == 1 && ns == 1360) {
        configure_ns(ns);  // Ответ B: если нужна поддержка
    } else if (current_profile == 1 && ns != 912) {
        set_error(STAT_NS_INVALID);  // Или молчи, если 912 норма
    } else if (current_profile == 2 && ns == 912) {
        configure_ns(ns);
    } else {
        set_error(STAT_NS_MISMATCH);
    }
    break;
```

**Тестирование:**
