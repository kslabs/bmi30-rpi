# Исправление: Автоматическое восстановление потока при зависании

## Проблема
При запуске BMI30.200.py программа зависала, пока устройство не было вручную сброшено. Механизм автоматического восстановления (`autoreset`) не срабатывал.

## Корневая причина
Функция `_try_connect()` выполняется в основном потоке GUI и может зависнуть при создании объекта `USBStream()` на строке 6730. Когда USB устройство не отвечает или занято:

1. Создание `USBStream()` блокирует GUI на неопределённое время
2. Функция `_tick()` не вызывается (UI заморожен)
3. Механизм проверки зависания в `_tick()` не может выполниться
4. Автосброс не срабатывает

## Решение
Переместили создание `USBStream()` в отдельный поток:

### Изменения в файле `/home/techaid/Documents/host/BMI30.200.py.2026-02-07-autoreset`

1. **Асинхронное подключение** (строка 6705+)
   - Функция `_try_connect()` теперь запускает рабочий поток вместо блокирующего вызова
   - Весь процесс подключения происходит в отдельном потоке

2. **Добавлен импорт `signal`** (строка 5)
   - Требуется для потенциального таймаута (зарезервировано на будущее)

### Преимущества
- ✅ GUI остаётся отзывчивым даже если устройство не отвечает
- ✅ `_tick()` продолжает вызываться каждый кадр
- ✅ Механизм проверки зависания срабатывает через 2 сек (по умолчанию)
- ✅ Автоматический аппаратный сброс выполняется без ручного вмешательства

## Как это работает теперь

```
Пользователь запускает программу
    ↓
_try_connect() сразу возвращается (не блокирует)
    ↓
в отдельном потоке: создаётся USBStream()
    ↓
пока поток создаётся, GUI останется отзывчивым
    ↓
_tick() проверяет состояние потока каждый кадр
    ↓
если нет данных 2+ сек → _maybe_auto_reset_on_stall() 
    ↓
→ SOFT_RESET через CDC
→ DEEP_RESET через bulk
→ аппаратный сброс GPIO
    ↓
Поток восстанавливается, и данные начинают поступать
```

## Тестирование

Чтобы проверить исправление:

```bash
# Запустить программу
./.usbvenv/bin/python host/BMI30.200.py.2026-02-07-autoreset

# Отключить устройство (или имитировать проблему)
# → программа должна измениться: "Поток пропал... сброс STM32"
# → через 2 сек срабатывает SOFT_RESET
# → затем DEEP_RESET
# → затем аппаратный сброс GPIO17 (импульс 100мс)
# → автоматическое переподключение

# Включить устройство обратно
# → поток восстанавливается
```

## Конфигурация

Переменные окружения остаются прежними:

```bash
export BMI30_AUTO_RESET_ON_STALL=1              # включить (по умолчанию)
export BMI30_STALL_RESET_AFTER=2                # таймаут в сек (по умолчанию 2)
export BMI30_STALL_RESET_COOLDOWN=10            # delay между попытками (по умолчанию 10)
export BMI30_HW_RESET_GPIO=17                   # GPIO для сброса (по умолчанию 17)
export BMI30_HW_RESET_PULSE_MS=100              # длительность импульса (по умолчанию 100)
export BMI30_HW_RESET_WAIT_S=3.0                # ожидание после сброса (по умолчанию 3.0)
```
